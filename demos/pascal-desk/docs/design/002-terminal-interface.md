## 1. Goal

Turn the reviewed editor model into an interactive Turbo Pascal inspired TUI. All production
implementation is delegated to DSH. File operations and find dialogs are the next phase.

## 2. Success criteria

- A real terminal displays blue editor/cyan frame/gray menu and shortcut bars, filename,
  dirty marker, line/column, and a visible cursor; edits and scrolling work with the keyboard.
- F1 help and F10 menu are navigable and dismissible. Menus dispatch the same intents as shortcuts.
- Output is clipped to terminal bounds and cannot execute control characters from text or filenames.
- Exit and handled errors restore raw mode, cursor and alternate screen. Non-TTY launch fails clearly.

## 3. Acceptance checks

```powershell
npm run check
npm run build
npm test
node dist/src/cli.js --help
```

Codex executes checks if the known DSH shell restriction persists. Do not attempt permission repair.

## 4. Scope

In: pure app controller, pure renderer, lightweight lexer, thin Node terminal adapter, tests.
Out: filesystem operations and find/prompt/confirmation flows (phase 3), compiler/debugger.

## 5. Design

### Public interfaces

`src/app.ts` exports:
- `KeyInput { name?:string; sequence?:string; ctrl?:boolean; meta?:boolean; shift?:boolean }`
- `Command = 'new'|'open'|'save'|'saveAs'|'find'|'quit'`
- `AppState` with `editor:EditorState`, `topLine:number`, `leftCol:number`, `status:string`,
  `overlay:'none'|'help'|'menu'`, `menuIndex:number` (additional fields allowed if needed).
- `createApp(editor?:EditorState):AppState`
- `handleKey(state:AppState, key:KeyInput, pageSize?:number):{state:AppState; command?:Command}`
- `fitViewport(state:AppState, visibleRows:number, visibleCols:number):AppState` keeping cursor visible.

Map Node keypress names: arrows, home/end, pageup/pagedown, return, backspace, delete, tab.
Printable input (`sequence`) inserts only if no ctrl/meta modifier; never insert escape sequences.
F1 toggles help. Escape closes overlay. F10 toggles menu; arrows choose menu action; Enter selects.
Ctrl+Z/Y undo/redo. Command shortcuts per product doc. Ctrl+C maps to quit intent as well.
Help/menu swallow typing and editor navigation; do not accidentally edit under an overlay.
Menu list: New, Open, Save, Save As, Find, Undo, Redo, Help, Quit. No compiler/run/debug items.
Status strings should be brief and honest. Phase 2 file/find command intents display 'Available in phase 3'.
Until phase 3, quit exits immediately; final dirty safeguards are mandatory in phase 3.

`src/syntax.ts` exports `highlightLine(text:string): {text:string; kind:'plain'|'keyword'|'string'|'comment'|'number'}[]`.
Recognize common Pascal keywords case-insensitively, numbers, single-quoted strings with doubled quote
escaping, `{...}` and `(*...*)` on a single line, and `//` comments. Preserve every input character;
this is lightweight single-line coloring, not parsing. Document multiline comment limitation later.

`src/render.ts` exports `renderScreen(state:AppState, columns:number, rows:number):
{output:string; cursor:{row:number;col:number}|null}`. Cursor is 1-based terminal coordinate.
Output is a complete frame of `rows` CRLF-separated lines, no trailing newline; each plain line uses
at most `columns-1` cells to avoid terminal autowrap. Caller prefixes cursor-home and applies returned
cursor. Sanitize ESC/C0/C1/DEL control bytes to visible placeholders; expand tabs for display only.
No escape bytes derived from buffer/status/path may reach terminal output; ANSI generated by renderer is allowed.
Fit viewport to editor area; e.g. menu row, filename/top border row, content rows, bottom border/status,
shortcut bar. Minimum supported size is 60x16; smaller size shows a clipped resize notice and hides cursor.
Use ASCII borders for consistent v1 width; recognizable classic colors matter more than exact clone.

`src/cli.ts`: parse `--help` first (success without TTY), unknown flags fail with usage, currently no
file loading (phase 3). Interactive requires both input/output TTY. Enable alternate screen/raw input,
listen via `readline.emitKeypressEvents`, render after input/resize, clean up listeners/raw/cursor/screen
exactly once on quit, SIGINT/SIGTERM, or caught error. Do not install global handlers on module import;
guard executable entry. Do not call process.exit before flushing cleanup. Implement reasonable dimensions
fallback. Optional exported terminal runner with injected streams is allowed for meaningful tests.

## 6. Implementation plan

| File | Change |
|---|---|
| `src/app.ts` | UI state, key-to-action/intent translation, viewport |
| `src/render.ts` | bounded styled frames and overlays |
| `src/syntax.ts` | safe lexical tokens |
| `src/cli.ts` | help, TTY lifecycle, interactive shell |
| `tests/app.test.ts` | shortcuts, modal isolation, scroll bounds |
| `tests/render.test.ts` | frame dimensions, small terminals, injection protection, lexer preservation |
| `tests/cli.test.ts` | non-TTY/help/argument checks (subprocess) and lifecycle if feasible |
| `package.json` | add start script and make test discover all compiled tests portably |

Existing `src/editor.ts` interface remains unchanged. No dependencies. Test discovery must actually
execute every test file (a JS glob supported by Node 22.14 or an explicit list is acceptable).

## 7. Constraints

No ANSI control sequences originating from file content. Rendering must not mutate app state.
Do not change phase 1 tests to hide regressions. Work only in named files. Aim for understandable,
small functions; avoid terminal libraries or an elaborate component framework.
